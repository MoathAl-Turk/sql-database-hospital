Hospital Management System Database

A comprehensive relational database designed and implemented from scratch to handle complex hospital operations.

1. Entity-Enhanced Relationship (EER) Modeling

The first step was designing the conceptual data model. This EER diagram maps out the complex relationships between patients, doctors, departments, and medical records.

2. Relational Schema & Normalization

After finalizing the EER model, I mapped it into a relational schema, applying strict normalization rules to eliminate data redundancy and ensure data integrity across all tables.

3. Oracle SQL Implementation

The final phase was bringing the schema to life using Oracle SQL. Below is a sample of the table creation and some of the complex querying used to retrieve patient history.

-- 1. Table creation utilizing Primary Keys, Foreign Keys, and CHECK constraints
CREATE TABLE Nurse(
    EmployeeID NUMBER PRIMARY KEY,
    ShiftType VARCHAR2(20),
    Ward VARCHAR2(30),
    OnCallStatus VARCHAR2(10)
    CHECK(OnCallStatus IN('On-call','Off-call')),
    FOREIGN KEY(EmployeeID) REFERENCES Employee(EmployeeID)
);

-- 2. Multi-table JOIN to retrieve complete patient and attending doctor records
SELECT P.FName,
       P.LName,
       E.Name AS DoctorName,
       T.Diagnosis
FROM Patient P
JOIN Treats T ON P.PatientID = T.PatientID
JOIN Doctor D ON T.DoctorID = D.EmployeeID
JOIN Employee E ON D.EmployeeID = E.EmployeeID;

-- 3. Advanced nested subqueries to filter patients based on specialist treatment
SELECT FName, LName
FROM Patient
WHERE PatientID IN
(
    SELECT PatientID
    FROM Treats
    WHERE DoctorID IN
    (
        SELECT EmployeeID
        FROM Doctor
        WHERE Specialty='Heart'
    )
);
